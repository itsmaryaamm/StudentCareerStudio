# Student Career Studio — frontend audit (pre-beta)

Method: the uploaded standalone prototype was rendered in headless Chromium at 1280×800 and 390×844,
every nav view was opened, and DOM-level checks were run (landmarks, labels, tap-target size, ARIA, console).
Console: no errors. No horizontal scroll at 390px. The visual identity is good and is kept.

## What is good (keep)

- Palette `#6d4bd8` (brand) / `#5436b8` / `#f4f1fc` tint / `#1d1b26` ink / `#6b6878` muted / `#ebe9f1` hairline; Plus Jakarta Sans; 16px card radius, 10px control radius.
- "Verify before saving" fact cards, the Gemini data-processing notice, "Information included" checkboxes on prompts, "We never post for you".
  These are the right product ideas and are implemented for real in the app.

## Findings

| #   | Area          | Finding                                                                                                                                                                                      | Severity | Resolution in the app                                                                                                      |
| --- | ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------- |
| 1   | Onboarding    | No onboarding. A new user lands on a dashboard full of fake data ("Welcome back, Layla", 3 résumés, 80% profile).                                                                            | High     | Real first-run flow: Start with AI / Import résumé / Import LinkedIn, shown until the user has any résumé or profile fact. |
| 2   | Product       | "Free plan, 18 of 40 AI messages", "Pro is coming later" contradict a free founding beta and mislead about limits.                                                                           | High     | Replaced by "Founding beta" and the real server-enforced daily/upload counters. No pricing UI.                             |
| 3   | Data          | Every number, name, résumé and profile fact is hard-coded; nothing persists.                                                                                                                 | Critical | All data comes from the API (Postgres).                                                                                    |
| 4   | Accessibility | Zero `aria-*`/`role` attributes; no `<html lang>`, empty `<title>`; nav items are non-semantic; the 5-icon glyph nav uses unicode symbols (⌂ ▤ ❝) that screen readers read aloud as symbols. | High     | Real `<nav aria-label>`, `aria-current`, labelled controls, `aria-live` for chat/loading/autosave, icons `aria-hidden`.    |
| 5   | Accessibility | 8 of 13 interactive targets < 44px on desktop (2 on mobile). Pills/“Accept / Reject / Copy” are ~28–32px high.                                                                               | Medium   | Min 44px hit area on touch breakpoints.                                                                                    |
| 6   | Accessibility | Chat has no live region; a streamed/new reply is invisible to a screen reader. Chat input has no accessible name (placeholder only).                                                         | High     | `role="log" aria-live="polite"`, labelled textarea, Enter-to-send with Shift+Enter newline.                                |
| 7   | Accessibility | Consent notice is dismissed by "I understand" but no focus management; dismissal state is lost on reload.                                                                                    | Medium   | Consent is stored server-side with a timestamp; AI calls are refused without it.                                           |
| 8   | Navigation    | Dashboard action grid: 5 cards in a 4-column grid leaves an orphan on row 2; on mobile it is five full-height cards that push résumés/profile below the fold.                                | Medium   | Responsive 2-col / compact action list on mobile; primary action first.                                                    |
| 9   | Navigation    | Mobile bottom nav has 6 items (too many for 390px, labels ~10px), no safe-area inset for iOS home bar.                                                                                       | Medium   | 5 items, `env(safe-area-inset-bottom)`, ≥44px targets.                                                                     |
| 10  | Navigation    | Desktop sidebar disappears on mobile with no way to reach account/sign-out except Settings.                                                                                                  | Low      | Account menu in the mobile header.                                                                                         |
| 11  | UX            | No loading, error, empty, offline or "saved" states anywhere. "Save" gives no confirmation.                                                                                                  | High     | Skeletons, inline retryable errors, empty states, "Saving… / Saved HH:MM" autosave indicator.                              |
| 12  | UX            | Chat: a failed AI call would just vanish; there is no quota message, no way to see remaining messages.                                                                                       | High     | Quota banner, friendly 429 messages with reset time, remaining count in the header.                                        |
| 13  | UX            | "Gemini suggestions" in LinkedIn Studio imply accept/reject but nothing is saved or sourced.                                                                                                 | Medium   | Suggestions come from approved facts only and list "Based on:"; accepted text is saved per section.                        |
| 14  | Privacy       | "Download my data / Delete my account" are dead buttons. "Uploaded documents aren't kept" is a claim with no backing.                                                                        | Critical | Real deletion (cascade), data export, and uploads processed in memory and never written to disk or DB.                     |
| 15  | Trust         | Footer says "Built on Reactive Resume (MIT). Not affiliated with its authors."                                                                                                               | Info     | Kept, and the MIT licence file is retained in the repo.                                                                    |
| 16  | Perf          | Design depends on unpkg React UMD at runtime.                                                                                                                                                | Low      | Not applicable once ported to the Reactive Resume build.                                                                   |
